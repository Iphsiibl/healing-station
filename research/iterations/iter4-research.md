# 迭代四调研：生存故事扩容 · 第二短篇 · 游戏厅第五款 · 每日彩蛋

> 时间：2026-11-17 · 对应版本：v1.9.0 · 方法：按「调研 → 审查 → 方案 → 实现 → 测试 → 快照/部署」六步流程执行，本文件是第一步的产出。
> 说明：所有结论都标注了来源；凡是根据二手信息推断的，一律标注「推测」。抓取失败的来源也如实记录。

## 一、本轮要解决什么

第三轮审查（`iter3-audit.md`）留下的缺口表里，有三条与本轮直接相关：

| 缺口 | 为什么要现在做 |
| --- | --- |
| 生存故事量级偏小（42 节点 / 6→7 结局），单次游玩 3~5 分钟就结束 | 故事是「被看见」的模块，量级不足会让高频用户 quickly 玩腻 |
| 游戏厅只有三类玩法（点击反应 / 交换消除 / 躲避弹幕），缺第四类 | 玩法重复会让游戏厅的新鲜感衰减 |
| 缺少「今天来做什么」的引导（每日彩蛋），也没有成就感的沉淀 | 参考产品的共同做法：每日一件小事 + 看得见的积累 |

## 二、可访问的源与本轮实际抓取到的内容

### 2.1 iTunes 中国区搜索 API（可访问，200）

接口：`https://itunes.apple.com/search?term=裁员&country=cn&entity=software&limit=12`

抓到两个与「被裁」高度相关的 App，description 是产品作者自己写的功能说明，属于一手材料：

**①《过招记 - AI面试辅助与裁员赔偿谈判指导》**（深圳闪爪科技，2026-09 上架）

- 价值主张原文：「这两种场景，都是开口之前就已经定输赢的…让你先在没人看见的地方，事先都练熟。」
- 裁员线的结构：**十五种局面**，从第一次约谈到仲裁前的最后博弈，典型四段是「约谈试探 / 绩效施压 / 调岗降薪逼退 / 逼签放弃协议」。
- 机制：先跟模拟 HR 过几招；按工龄、月薪、城市社平工资算清 N / N+1 / 2N；上传真实谈话录音做逐句复盘。
- 它的自我描述里有一句关键的产品判断：「HR 找你聊之前已经排练过，你是第一次上桌。」

**②《裁员补偿指南 - 离职赔偿计算与谈判取证技巧》**（个人开发者，2026-05 上架，¥18）

- 功能被拆成四个维度：**资格判定 / 精准计算 / 证据梳理 / 面谈话术**。
- 话术库按 **HR 面谈的不同阶段** 给脚本与避坑策略——也就是说，作者认为「阶段」比「场景」更适合当剧本骨架。
- 免责声明写得很克制：「计算结果、法律条款索引及话术建议仅供逻辑模拟与参考，不构成正式的法律意见或专业咨询建议。」

**③ 旁证：《我的阳台菜园》**（2026-04 上架）用了 **6 个成就徽章**（新手园丁 / 浇水达人 / 丰收时刻 / 园艺专家…），并且所有数据「保存在本设备，不上传服务器」——这正是本站「数据只存在你自己的浏览器里」的同款选择，徽章数量 6 个这个具体数字可以借鉴。

### 2.2 百度热搜 · 挑战榜（可访问，200）

接口：`https://top.baidu.com/api/board?platform=wise&tab=challenge`

榜单规则写明「每 24 小时更新」，上榜内容多为**轻量互动型**主题：秋日花海穿搭秀 / 测一测你是什么命 / 对烦恼说拜拜 / 奔波在路上 / 旅途日常记录 / 记录旅途日常。

**观察**：挑战榜的内容形态是「每天一个可以马上参与的小仪式」——参与门槛极低、周期恰好一天。这正好是我们「每日彩蛋」的形态参考：不做任务系统，做「今天来个小东西」。

### 2.3 前几轮已抓到的、可复用的源

- iTunes 中国区「心理压力」搜索（迭代一）：Winsomely 的机制是「每天 3 分钟小练习 + 经验值等级 + 连续打卡 + 进步记录」，并强调「先练一遍」——故事模块的「先在没人看见的地方练一遍」定位与之同源。
- iTunes 中国区「白噪音」搜索（迭代三）：潮汐 / 小睡眠都把**冥想场景化**（专注、孤独、午休、通勤）与**呼吸法**做成独立入口。

## 三、结论

- **C1｜故事按「阶段」而不是「场景」搭骨架更耐打。** 依据：《裁员补偿指南》把话术按 HR 面谈阶段分档；《过招记》把十五种局面排成一条从约谈到博弈的线。因此第二短篇《被裁的那天》按 **约谈试探 → 绩效施压 → 调岗降薪 → 逼签放弃协议 → 取证与协商** 五个阶段推进，而不是散点式场景。
- **C2｜「先练一遍」是这类内容的核心价值，但必须明确不是法律咨询。** 依据：两个 App 都把免责声明放在显著位置。我们照做：第二短篇**不引用法律条文、不计算任何具体赔偿数字、不给法律建议**，只做情境演练与情绪支持，站点免责声明同步复述。
- **C3｜主篇也要扩容，但方式不同。** 依据：站内审查显示主篇 42 节点已偏薄。本轮给主篇补 18 个节点、3 个结局（旧文一字不改），补充的支线来自第一轮调研里已经出现过的真实职场琐事（远程办公、周五最后 15 分钟、电梯遇到老板、外卖错单、工位调整…），避免凭空编造。
- **C4｜游戏厅要补第四类玩法。** 现有三类是「点击反应 / 交换消除 / 躲避弹幕」。工作群里最常见的紧张时刻是 **「消息已经发出去了，能不能在两分钟内撤回来」**——这是点击 + 时限 + 误判（不是每条消息都该撤回）的组合，正好是第四类玩法。故新增第 5 款《撤回消息》。
- **C5｜每日彩蛋要做成「一天一件小事」，不要做成任务系统。** 依据：百度挑战榜的内容形态（每 24 小时更新、门槛极低的小仪式）。本轮做 12 条轻量彩蛋，按日期确定性轮换，完成状态只存在本地。
- **C6｜徽章留到第五轮。** 依据：《我的阳台菜园》的 6 枚徽章。本轮只做故事/游戏/彩蛋，徽章与连续天数属于周报模块，留给 v1.10.0。

## 四、本轮明确不做的事

1. 不做赔偿计算器、不引用劳动法条文——本站不提供法律建议（内容守则）。
2. 不做多音轨混音（潮汐那套）——Web Audio 混音需要重做音频架构，收益低于风险，留到以后。
3. 不做成就系统——归到 v1.10.0 的周报模块一起做，避免数据落盘格式改两遍。
4. 不给故事加音效配乐——故事是文字模块，音效留白更安静。
