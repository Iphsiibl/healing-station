# 迭代一审查报告 · 六个模块的「体检单」

> 时间：2026-11-17 ｜ 审查工具：`healing-station/tools/audit.js`（零依赖，`node tools/audit.js`，加 `--json` 可出结构化结果）
> 审查对象：情绪急诊室 / 社恐话术机 / 摸鱼补给站 / 今日生存小游戏 / 疗愈周报 / 摸鱼游戏厅 + 全站文案卫生

## 一、怎么审的

审查不是「看一眼觉得还行」，而是让机器把六件事量出来：

| 检查 | 做法 | 抓什么 |
| --- | --- | --- |
| 条目数 | 数数据文件里的条目 | 哪个模块内容太薄 |
| 字段完整率 | 逐条查字段是否存在且非空 | 少字段的「半成品」文案 |
| 矩阵完整率 | 场景 × 语气 的每格是否都有 ≥3 条 | 某些组合是空的 |
| 近重复检测 | 归一化后算字符集 Jaccard，≥0.75 报警 | 两句话其实说的是同一件事 |
| 可达性 | 复用引擎里的 `storyReach()` | 玩家永远走不到的结局 |
| 全站卫生 | 扫乱码 `�`、营销腔英文、失效引用、emoji 密度、免责声明 | 「看起来很努力但其实有坑」 |

分级：完全相同 = ❌ ERROR（必须改）；相似或提示 = ⚠️ WARN（记录并判断）；通过 = ✅；纯统计 = ℹ️。

## 三、本轮审查抓到的问题与处理

| # | 问题 | 处理 |
| --- | --- | --- |
| 1 | 情绪库里有近似重复的祝福（Jaccard 0.88），读起来像同一句话说了两遍 | 改写重复的那一条；复扫全库 114 条祝福，相似度全部 < 0.45 |
| 2 | 关键词包与新心情之间有内容级撞车：「通勤」心情的处方和旧「通勤」包几乎同句 | 整组重写为「换一站下车 / 车上先坐会儿 / 换乘时走楼梯 / 前夜把东西备好」 |
| 3 | 故事 4 个环可能导致玩家永远走不到结局 | 引擎加 `maxSteps: 40` + `loopEnding: 'end_drift'`，走到上限强制落到「绕圈型」结局；并新增 `end_drift` 结局与可达路径（focus 节点第三个选择） |
| 4 | 节点标题重复：`calm` 与 `quiet` 都叫「安静的十分钟」 | `quiet` 改为「只有空调声的十分钟」 |
| 5 | 选项撞标题：「茶水间，哭了五分钟」既是选项又是节点标题 | 选项改为「去没人的地方哭五分钟」 |
| 6 | 选项撞选项：「再坐一会儿，什么都不想」≈「什么都不做」 | 改为「什么都不想，先缓一会儿」 |
| 7 | 诊断单只有 3 条处方，用户要来回点「换一张」才看全 | 改为**一次列全**处方；新增 `checkup` 复诊提醒字段与 UI 区 |
| 8 | 关键词包只能按包名命中（写「被优化」识别不到「裁员」包） | `matchPacks()` 支持包内 `keywords` 同义说法数组，18 个包共 100+ 种说法，大小写不敏感 |
